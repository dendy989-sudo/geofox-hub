# Alfred connected operations — November 6, 2026

Entry: owner-only Alfred → Workflows & connections. Accounting → Provider billing reports opens the billing tools. These workflows are not an unattended company operator.

## What is implemented

- Production checks every ten minutes. Up to one support/incident model run per check and a shared configurable daily cap (default 8). Existing Alfred concurrency, daily/monthly spending, consent and pause checks remain authoritative. One-shot claims and event IDs prevent duplicate model runs for the same customer message; unresolved reply proposals block replacement drafts. Sensitive account, billing, legal or safety language is escalated without an automatic response. This classifier is conservative, not a replacement for human review.
- Support drafts use the existing exact-reply approval workflow. All customer replies still require owner approval. Email/web guest senders remain unverified; email address matching never establishes account ownership.
- Signed Resend receiving webhook with raw-body HMAC/timestamp verification, payload bounds, rate limit, provider-email-ID dedupe, fixed receiving API and an explicit recipient allowlist. Text only; no attachment downloads or executable HTML. Every inbound email starts in owner review. Approved routing creates a new unverified ticket, not a merged customer account/thread. Forwarded original senders are not inferred from body text.
- Owner-only test email, sent only to the signed-in verified owner's address. Provider acceptance is distinguished from inbox delivery. Neither the test nor intake is active without server credentials.
- Vercel FOCUS billing reads using the already configured Vercel credential where permissions allow. Hourly report cache; billing failures remain explicit. Conditional GitHub enhanced-billing usage adapter with its own Plan-read credential. Reports show only returned source coverage and are not treated as payments or automatically added to cash totals.
- Atomic invoice import: exact service/invoice references deduplicate a batch and previous imports; changed duplicates require review, and invalid rows roll back the entire batch. Owner statements of paid/unpaid status are not bank verification. Receipts are attached in Accounting.
- Exact approved Facebook/X text-post scheduling. The version, account and timestamp are approved by the owner; source changes invalidate the job. Only one delivery attempt; overdue windows or uncertain outcomes require review, not blind replay. Reuses existing identity-checked publishing adapters. Global Alfred pause stops new publications.
- Owner-triggered Facebook/X metrics reads for posts actually published by the exact connected account. Missing metrics remain unknown. Facebook reactions are requested as LIKE only, not all reactions mislabeled as likes.
- Branded square/vertical PNG typography templates from owner-entered copy. Saved to private Marketing storage and attached only to an unchanged empty-media draft. No paid generative image model or automatic public publication. Not a video producer.
- Separate bounded UI repair workflow: select up to two existing presentation files (16 KB each), snapshot an exact source commit, propose replacements using the shared model allowance, then review exact before/after text. Only a separate explicit approval can create a deterministic repair branch and DRAFT PR. No SQL/auth/billing/admin/infrastructure/workflow files. Stale bases fail closed. No merge, branch-protection changes, production deployment or automatic rollback. UI path/string checks are defense in depth, not proof a generated patch is safe; human review is mandatory.
- Hub-specific PR CI for Alfred repair branches: install, typecheck, tests, build. Uses pinned actions, read-only permissions, no stored credentials and a 12-minute job timeout. GitHub Actions quota and Vercel preview-build billing still apply. No CI result is fabricated when a job cannot run. NovaNook uses its own existing CI; this release does not modify the Booknook repository.

## Required account connections — not performed by code

1. Verify a sending domain with Resend. Set `RESEND_API_KEY` and `SUPPORT_FROM_EMAIL` in the production Vercel project (support@geofoxapps.com or support@notify.geofoxapps.com). Use the owner test and confirm receipt. Cost alerts use that same verified sender. No delivery verification is claimed just from variable presence.
2. Preserve GoDaddy's root MX records. Use a Resend receiving address or a separate receiving subdomain and forward the support mailbox to it. Configure `email.received` webhook at `https://www.geofoxapps.com/api/alfred/inbound`, `RESEND_WEBHOOK_SECRET`, and comma-separated `ALFRED_INBOUND_ADDRESSES`. Do not forward unrelated personal/company mail. Test the actual forward with a benign message, then review it in Alfred.
3. Set exact scoped Facebook Page or X credentials in `MARKETING_SOCIAL_ACCOUNTS` using `docs/social-connections.md`. Saving a profile handle is not authorization. Instagram, TikTok, videos, comments/DMs, live external market research and paid ads are not integrated here. TikTok's current Direct Post intended-use rules exclude utilities for accounts managed by your own team; use an eligible partner/native workflow, not a bypass.
4. Set `GITHUB_BILLING_TOKEN` with user Plan read access for billing. Set `ALFRED_GITHUB_TOKEN` separately for ONLY the selected company repositories: contents and pull requests write; actions/checks read. ChatGPT's connector authorization is not an application runtime token. Never paste tokens into Alfred, knowledge, issues, or chat.
5. Actual Supabase/Google/GoDaddy/app-store/Codemagic invoices and limits need verified records or further provider adapters. App database keys do not grant billing access. Bank feeds, tax filing, app-store payout reconciliation and automatic financial payments remain outside this release.

## Safety and verification

RLS with revoked browser-role privileges on all new tables; RPCs are service-only/security-invoker and independently verify a live owner. Owner routes use existing session/MFA and same-origin protections. Native cron requires CRON_SECRET and production context. No action trusts model text as permission. Invoice, email, model, schedule and repair identifiers have explicit replay behavior. Private household Finance is never queried.

Run `npm run test:ops`, `npm run typecheck`, `npm test`, `npm run build`. Tests include signature tampering/freshness, size limits, owner/RLS restrictions, safe email identity, dedupe/daily caps, approval versions, pause, late jobs, one-shot repairs, invoice atomicity and escaped UI rendering. Account-dependent end-to-end tests require owner-connected credentials. Keep those limitations visible in release notes.

Rollback: disable operations first, then roll back application if required. Retain additive audit/accounting tables; don't delete customer evidence as routine rollback. Pausing cannot recall already submitted provider requests.

References checked: Resend receiving and webhook verification; Vercel FOCUS billing charges; GitHub billing usage; TikTok content sharing intended use. Provider APIs and permissions must be reverified when connecting real accounts.
